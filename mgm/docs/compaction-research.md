# Context compaction for LLM coding agents (state of the art, Sept 2026) — with a plan for pi on a 32k local model

## 1. How pi's built-in compaction works (v0.85.1, read from `dist/core/compaction/*.js` and `docs/compaction.md`)

**Trigger.** `shouldCompact()` fires when `contextTokens > contextWindow - reserveTokens` (`reserveTokens` default **16384**, `keepRecentTokens` default **20000**, settable in `~/.pi/agent/settings.json` or `.pi/settings.json`). Context tokens come from the last assistant `usage.totalTokens` plus a chars/4 estimate of trailing messages. It is checked before a user prompt, between tool results and the next assistant call, and after a run. There is no percentage mode; issue [#9486](https://github.com/earendil-works/pi/issues/9486) (budget independent of the window) was closed "no-action".

**Overflow path.** If the provider rejects the request (`isContextOverflow`), pi runs `_runAutoCompaction("overflow", willRetry)` **exactly once** (`_overflowRecoveryAttempted`); a second failure ends with "Context overflow recovery failed after one compact-and-retry attempt" (`agent-session.js`).

**What it summarizes and how.** `prepareCompaction()` walks backwards accumulating estimates until `keepRecentTokens`, cuts at a user/assistant/custom message (never a tool result), and everything older (back to the previous compaction's `firstKeptEntryId`) becomes `messagesToSummarize`. Those are serialized to text (`[User]:`, `[Assistant]:`, `[Tool result]:`; tool results truncated to **2000 chars**, `utils.js`) and sent **in one request to the same model** as a single user message under `SUMMARIZATION_SYSTEM_PROMPT`, with `maxTokens = min(0.8 * reserveTokens, model.maxTokens)` and `cacheRetention: "none"`. If a previous summary exists it is included in `<previous-summary>` and the "UPDATE" prompt is used (iterative accumulation). A "split turn" (one turn > keepRecentTokens) triggers a second request for the turn prefix (`maxTokens = 0.5 * reserve`); the two are concatenated. Summary format: Goal / Constraints / Progress (Done, In Progress, Blocked) / Key Decisions / Next Steps / Critical Context, plus `<read-files>`/`<modified-files>` extracted from tool calls. Recent turns past the cut point are kept verbatim.

**Failure handling.** `getSummarizationFailure()` rejects `stopReason === "length"` (truncated summary is never persisted) and errors; a tool call in the response also throws. `completeSummarization()` wraps the call in `retryAssistantCall` (retry settings: 3 attempts, 2s backoff) — but overflow errors are not retryable.

**Hooks.** `session_before_compact` (return `{cancel:true}` or a full `{compaction:{summary, firstKeptEntryId, tokensBefore, usage, details}}`; receives `preparation`, `branchEntries`, `reason`, `willRetry`, `signal`), `session_compact`, `session_compact_failed`, `ctx.compact({customInstructions,onComplete,onError})`, and the per-request `context` event (deep copy of messages; return `{messages}` to prune transiently). `examples/extensions/custom-compaction.ts` shows summarizing with a different model via `ctx.modelRegistry.complete()`.

**Why it fails at 32k.**
- The summarization request has **no input cap**: with defaults it sends ~ (32k − 16k reserve − 20k keep) ≈ everything older than 20k, plus the prompt, plus previous summary, to a model that already has 32k of context. Once overflowed, "the request meant to shrink the context is the same size as the context that overflowed" — [#8371](https://github.com/earendil-works/pi/issues/8371), closed no-action.
- `keepRecentTokens (20k) + reserveTokens (16k) > 32k`, so threshold compaction triggers at 16k, keeps 20k, and often has nothing older to summarize ("Nothing to compact", [#6751](https://github.com/earendil-works/pi/issues/6751)) or lands in a split turn.
- If the LM Studio model has no `contextWindow` in `models.json`, pi assumes **128000** (`docs/models.md`), so the threshold never fires and you only hit the single-shot overflow path. Local OpenAI-compatible providers also historically reported zero usage ([#4497](https://github.com/earendil-works/pi/issues/4497); partially addressed by estimate fallback, [#8328](https://github.com/earendil-works/pi/issues/8328)).
- Long tool loops can push past the window before the between-turn check ([#5512](https://github.com/earendil-works/pi/issues/5512)); tool results are capped at 50KB/2000 lines (`tools/truncate.js`), i.e. ~12k tokens each.
- Summary output budget is 0.8 × 16384 ≈ 13k tokens with no lower cap; a verbose 35B model can hit `maxTokens` → "length" → discarded.

Common pattern: **prune tool results first, summarize second, keep a recent raw tail, and use a cheap model** (Aider, Cursor, OpenHands, Claude Code microcompact).

## 3. Research techniques

- **Observation masking ≈ summarization.** JetBrains' *Complexity Trap* ([arXiv 2508.21433](https://arxiv.org/abs/2508.21433), NeurIPS DL4C 2025): hiding tool observations older than ~10 turns halves cost and matches/exceeds LLM-summary solve rate on SWE-bench Verified across 32B–480B models; hybrid (mask, then summarize a big batch occasionally) saves another 7–11% ([blog](https://blog.jetbrains.com/research/2025/12/efficient-context-management/)). Summary calls alone cost >7% per instance.
- **Task-conditioned tool-output pruning.** Squeez ([2604.04979](https://arxiv.org/abs/2604.04979)) fine-tunes a 2B Qwen to keep the smallest verbatim evidence block: 92% input removed, beats zero-shot Qwen 3.5 35B.
- **Generic prompt compression does not transfer.** LLMLingua-2 collapses on agent tasks past ~30% compression because it destroys structure ([ACON 2510.00615](https://arxiv.org/pdf/2510.00615), [AGORA](https://arxiv.org/pdf/2605.26596)).
- **Proactive/structured memory.** AgentFold ([2510.24699](https://arxiv.org/abs/2510.24699)) and Context-Folding ([FoldAgent, ICML'26](https://github.com/sunnweiwei/FoldAgent)) let the model fold sub-tasks into multi-scale notes; ACON optimizes compressor prompts; scratchpad/notes files (Cursor's transcript file, Manus's file system as memory).
- **KV-cache awareness.** Manus: stable prefix, append-only, deterministic serialization; never rewrite old messages mid-session ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)). On LM Studio/llama.cpp, rewriting the prefix forces a full re-prefill of 30k tokens — so prune in **batches at boundaries**, not per request.
- **Incremental compaction.** Aider's recursive halving and issue #8371's proposal: fold chunks into a running summary so no single request exceeds a budget.

## 4. Prioritized recommendations for pi at 32k (LM Studio, Qwen 3.6 35B-A3B)

1. **Fix the config first (no code).** Set `contextWindow: 32768`, `maxTokens: 4096` for the model in `models.json`, and `"compaction": {"reserveTokens": 6000, "keepRecentTokens": 8000}`. Trigger then lands ≈ 82% (26.7k) with ~19k to summarize and a ~4.8k summary cap. Gotcha: `maxTokens` in models.json also caps normal generation; `maxTokens` for summaries is `min(0.8×reserve, model.maxTokens)`.
2. **Observation masking via `context` event.** Replace tool results older than the last N (e.g. 8) tool calls, or larger than ~1.5k chars, with `[output elided: read foo.ts, 412 lines]`, keeping the `toolCall` block. Non-destructive, cheapest, most evidence-backed. Gotcha: the `context` hook fires every request, so mask only messages before a stable boundary (e.g. the last user turn) to keep the KV prefix stable; the session file still holds full outputs.
3. **Chunked summarization in `session_before_compact`.** Serialize `messagesToSummarize` (+`turnPrefixMessages`), split into chunks ≤ ~12k tokens (chars/4), fold each into a running summary using pi's own UPDATE prompt text, each request ≤ 50% of the window. Return `{compaction:{summary, firstKeptEntryId: preparation.firstKeptEntryId, tokensBefore, usage}}`. Gotcha: `reason === "overflow"` means the model is already stuck — chunking is what makes this path succeed; honor `event.signal`.
4. **Summarize with a cloud model via LiteLLM.** `ctx.modelRegistry.find("litellm", "…")` then `ctx.modelRegistry.complete(model, {messages}, {maxTokens, signal, cacheRetention:"none", sessionId: uuidv7()})` exactly as `custom-compaction.ts` does; fall back to chunked local if unreachable. Gotcha: the summary is then written by a stronger model but read by Qwen — keep it plain markdown, no XML beyond the file lists.
5. **Hard cap summary length** at ~2.5–3k tokens (`maxTokens`) and re-ask "shorten to ≤N words" if `stopReason === "length"` instead of failing; pi's own path discards length-stopped summaries.
6. **Structured template + running notes file.** Use pi's sections (goal, constraints, done/in-progress/blocked, decisions, next steps, critical context, files) and also append each summary to `.pi/notes.md`; register a `notes_read` tool or inject the last notes via `before_agent_start` so post-compaction turns can recover detail (Cursor's transcript-file trick). Persist state with `pi.appendEntry()` custom messages.
7. **Earlier, cheaper trigger.** A `turn_end` hook (as in `examples/extensions/trigger-compact.ts`) calling `ctx.compact()` at ~70% of `ctx.getContextUsage()`; also mask per (2) before the built-in threshold ever fires so overflow becomes rare.
8. **Cap tool outputs at the source.** Wrap `read`/`bash`/`grep` with `tool_result` hooks that head/tail to ~4k chars for this provider (pi's default is 50KB).

**Existing packages.** [pi-context-prune](https://github.com/championswimmer/pi-context-prune) (`pi install npm:pi-context-prune`) — summarizes completed tool-call batches with a configurable cheaper model, prunes originals via `context`, keeps an index; the closest to "smarter compaction" today. [pi-context-tools](https://github.com/theduke/pi-context-tools) — `context_info`/`compact_context` tools so the agent can self-compact. [billion-context-pi](https://github.com/boundring/billion-context) — proxy-level model-driven layered compression, prefix-cache friendly. [narumiruna/pi-extensions](https://github.com/narumiruna/pi-extensions): `pi-typesafe-compact`, `pi-codex-compact`. Memory-oriented: `pi-memory`, `pi-hermes-memory`, `@amaster.ai/pi-memory-mem0` ([pi.dev/packages](https://pi.dev/packages)). None does chunked summarization sized to a 32k window; that piece still needs a custom extension (items 3–5).
